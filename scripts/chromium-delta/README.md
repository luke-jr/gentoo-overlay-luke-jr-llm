# Upgrade patches for a Chromium version without a tarball

When a Chromium release has no source tarball yet, `www-client/chromium` can be built from
an older tarball plus a patch with the upstream changes between the two versions (a `_pre`
ebuild), and later changes of the release branch can be added the same way (a
`*-branch-fixes.patch`). These scripts make such patches, and check them.

The patches only carry what can affect this overlay's Linux build (see `filter.py` for the
rules), and the files the tarball process generates, which aren't in git (see below).

## Making a patch

Work in a directory outside the overlay, e.g. `upstream/diff<NEW>`.

1. **The changed dependencies:** `deps.py changed DEPS.OLD DEPS.NEW`. Fetch DEPS at
   both versions from Gitiles (`+/refs/tags/<version>/DEPS?format=TEXT`, base64).
   - Git dependencies get a diff (step 2).
   - A `nongit` line is a CIPD package or GCS object that changed. Its files are in the
     tarball, but a diff can't carry them. Decide case by case: use the system's package,
     or download the new one in the ebuild.
   - `gclient_gn_args` means `build/config/gclient_args.gni` (read by gn) changes:
     regenerate it.
2. **The diffs:** `fetchdiff.sh NAME URL OLD NEW` for chromium/src (`refs/tags/OLD`,
   `refs/tags/NEW`) and each changed dependency. It takes Gitiles' diff (one request) and
   fetches only the two trees (blobless, depth 1), to check that the diff has every changed
   file. Gitiles leaves out binary files' contents: the script fails on one, which then
   needs another source.
3. **The base tree's file list:** the files of the tree the patch applies to. For a
   tarball, its listing. After earlier patches, a git index with them applied
   (`git read-tree`, `git apply --cached`, `git ls-tree -r`). The stamp files listed
   below aren't in git, so add their paths.
4. **The build inputs:** from a build of the base version: `ninja -t inputs chrome
   chromedriver chrome_sandbox` (paths relative to the source root) and GN's
   `out/Release/build.ninja.d`.
5. **Filter:** `filter.py [--branch-fixes] OUT TREE_FILES INPUTS src.diff: v8.diff:v8/ ...`.
   `OUT/report.tsv` has every file with its decision and the reason. Read the "other
   (kept to be safe)" ones.
6. **The generated files:** run `tarball-generated.py` on the base tarball (once per base
   tarball). Every file it lists must be covered by `generated.conf`, either regenerated or
   left out with a reason. Then `stamps.py BASE_DIR REF DEPS.NEW` writes the stamps' diff.
7. **Assemble:** the kept diffs with their prefixes (`diff --git a/<prefix>...`,
   `---`/`+++`, rename/copy lines), then the stamps' diff. Add a header saying where it
   comes from, what's left out and what was checked.
8. **Check:**
   - It applies to the base tree (`git apply --cached` to the index of step 3, not in the
     build).
   - chrome/VERSION is NEW, except with `--branch-fixes`.
   - Every patched file is byte-identical to its version at NEW: its `git hash-object`
     is the blob id in `repo-NAME`'s tree at `refs/x/new` (`git rev-parse
     refs/x/new:PATH`, nothing downloaded).

When the real tarball comes out:

- run `compare-tarball.py` on a tree that has only the upgrade patches applied;
- every UNEXPECTED line is a mistake to fix, or a rule to add (and note below);
- then switch the ebuild to the tarball.

## Generated files (generated.conf)

Files of the tarball that are in no git repository (`tarball-generated.py`). Run it on
each new base tarball, with generated.conf: it fails if a file is neither part of a CIPD or
GCS dependency nor covered by generated.conf. In 156.0.8078.12's tarball, 37201 such files:

| Count | What |
|---|---|
| 32752 | CIPD packages and GCS objects from DEPS (and recursed DEPS): node_modules, Python, the Go toolchain of webpagereplay, ... |
| 6 | stamps (`stamp`): regenerated by `stamps.py` |
| 1 | `build/config/gclient_args.gni` (`derived`): from DEPS' gclient_gn_args |
| 4439 | left out (`omit`), each with its reason: GN's source, depot_tools' downloads, upstream PGO profiles, hook outputs the build doesn't read |

## Notes: what was wrong, what was intentional

Each entry says what was found, and whether it was wrong or intentional. For the wrong ones
it also says what fixes it.

### 156.0.8078.47 (patches 156.0.8078.12 → .35 → .47, compared with Google's .47 tarball)

Comparing the upgraded tree with the real tarball turned up 650 differences.

**Intentional (by the rules):**
- Translations other than en-GB: Chromium's `.xtb` files and DevTools' locale files.
- Tests, test data and docs.
- Other platforms' files.
- ICU's data variants Linux doesn't use: `cast/` and `chromecast_video/` icudtl.dat,
  big-endian `common/icudtb.dat`, and `tzres/*.res`. Linux uses `common/icudtl.dat`
  (`icu_use_data_file=false`), which the patches update.

**Wrong:**
- **Stamps.** `skia/ext/skia_commit_hash.h`, `gpu/webgpu/DAWN_VERSION` and
  `gpu/webgpu/dawn_commit_hash.h` stayed at .12's values. The patches only updated the
  stamps I knew of (`build/util/LASTCHANGE{,.committime}`, `gpu/config/gpu_lists_version.h`).
  Effect: chrome://gpu and WebGPU's adapter info showed .12's Dawn and Skia hashes.
  - Fix: `tarball-generated.py` lists all such files mechanically, `generated.conf` must
    cover each, and `stamps.py` writes all six.
- **Upstream profiles.** The headers said PGO pointers "for other platforms" were left
  out, but the filter dropped Linux's (`chrome/build/linux.pgo.txt`) too. The profiles
  themselves (`chrome/build/pgo_profiles/*.profdata`, `v8/tools/builtins-pgo/profiles/`)
  are hook downloads, which a diff can't carry. Effect: none. The ebuild builds with
  `chrome_pgo_phase=0`, or with its own profile under `USE=pgo`. V8's builtins profiles
  need `chrome_pgo_phase=2` and V8's external code space, which the ebuild turns off.
  - Fix: `filter.py` now drops them under its own rule, with the real reason, and the
    headers say so.
- **CI configuration.** The filter kept `infra/` (CI configuration) "to be safe", while
  the branch fixes' header said infra files were left out.
  - Fix: `filter.py` drops `infra/` under its own rule.
- **Translations kept.** The filter checked "a build input" before "a translation", so
  it kept the translation files the build reads. The headers said they were left out.
  Fixed in the patches, and in `filter.py` (translations come first).

**Not checked before, checked now:**
- **CIPD and GCS dependencies.** Changes of DEPS' CIPD packages and GCS objects
  (node_modules, prebuilt tools, test data) weren't looked at; only git dependencies were.
  None changed from .12 to .47. `deps.py changed` now reports them.
- **Hook outputs.** `build/config/gclient_args.gni` (gn reads it) is written by gclient
  from DEPS' `gclient_gn_args`. They didn't change from .12 to .47. `deps.py changed` now
  reports when they do. The other hook outputs (`.landmines`, siso's configuration,
  `chromeos/tast_control.gni`, `testing/location_tags.json`) aren't read by the Linux build.

### 157.0.8103.32 (patch 157.0.8103.30 → .32)

**Wrong:** `fetchdiff.sh` made the diff with `git diff` in the blobless fetch, so git
downloaded every changed file's old and new contents, one request each: over 10 minutes
for chromium/src's 59 files. Fix: the script takes Gitiles' diff instead, and fetches only
trees. The byte checks use the trees' blob ids, so they download nothing either.
